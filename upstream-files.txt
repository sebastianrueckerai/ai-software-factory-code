# Every file the factory's builds download from outside (roadmap 203,
# step 1), one per line: a file's package name, version, file name, URL
# and sha256. scripts/upstream-files uploads each into the factory's
# store, org upstream of git.aisoftwarefactory.world, under its generic
# package registry path
# /api/packages/upstream/generic/<package>/<version>/<file>, only when
# the store lacks it, after checking the download against the line's
# sha256. The lines name every ADD download of Dockerfile.runner and
# Dockerfile.sandbox and the build VM's buildkit tarball
# (internal/factoryd/buildvm.go); since roadmap 203's step 2 the builds
# read the store's copy at that path with the line's sha256, so the URL
# names only where the copy job takes the bytes from, and a pull
# request's build reads only what main CI already copied. Go's module
# cache and the npm cache of the sandbox image's opencode plugin lockfile
# ride the same registry as the go-modules and npm-cache tarballs
# scripts/upstream-files makes of them: the module tarball keeps the
# GOPROXY file layout and the npm tarball _cacache, and the builds
# restore and install from them with no upstream. The weekly upstream
# card bumps these lines.
